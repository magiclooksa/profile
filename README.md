# الملف التعريفي لمؤسسة النظرة الساحرة MAGIC LOOK

موقع يعرض الملف التعريفي للمؤسسة بهويتها: الشعار، والأوكر والأسود والعاجي، وخطا Noto Kufi Arabic وAlmarai. مكتوب بـ TypeScript دون أي إطار عمل.

الموقع ديناميكي: محتواه وصوره وفيديوهاته محفوظة في قاعدة بيانات **MongoDB**، ويُعدَّل من **لوحة تحكم** دون لمس الكود، ونموذج «اطلب استشارة» يحفظ طلبات الزوار. إذا لم يتوفر الخادم (مثل نسخة GitHub Pages) يعمل الموقع كما كان من ملفات JSON في `public/data`.

## التشغيل

يحتاج Node.js 22.9 أو أحدث.

```bash
npm install
npm run dev        # تشغيل محلي على http://localhost:5173
npm run build      # فحص الأنواع ثم بناء نسخة النشر في مجلد dist
npm run preview    # معاينة نسخة النشر
npm test           # الاختبارات
```

ارفع محتوى مجلد `dist` إلى أي استضافة ملفات ثابتة (Netlify، Vercel، GitHub Pages، أو استضافة عادية). المسارات نسبية، فيعمل الموقع من أي مجلد.

### النشر على GitHub Pages

المشروع يحتاج خطوة بناء؛ نشر `index.html` الموجود في جذر المستودع مباشرة سيعرض صفحة فارغة لأنه يشير إلى ملف TypeScript المخصص للتطوير.

1. ارفع تعديلات المشروع كاملة، بما فيها `.github/workflows/deploy.yml`، إلى فرع `main`.
2. افتح إعدادات المستودع **Settings → Pages → Build and deployment** واختر **GitHub Actions** في حقل **Source**.
3. من تبويب **Actions** شغّل **Deploy to GitHub Pages → Run workflow**، أو ارفع تعديلاً جديداً إلى `main`.
4. انتظر نجاح مرحلتي `build` و`deploy`، ثم افتح `https://magiclooksa.github.io/profile/`.

يبني سير العمل الموقع ويفحصه ثم ينشر محتويات `dist` فقط، بما فيها الصور وملفات `data`. لا حاجة لإضافة `dist` إلى Git؛ كل رفع لاحق إلى `main` يعيد النشر تلقائياً. إعداد `base: './'` يجعل مسارات النسخة المبنية تعمل داخل `/profile/` أيضاً.

## الموقع الديناميكي: قاعدة البيانات ولوحة التحكم

```
المتصفح ──► خادم Node.js (Express) ──► MongoDB
             ├─ /            الموقع المبني (dist)
             ├─ /admin.html  لوحة التحكم
             └─ /api/...     المحتوى، والملفات، والرسائل
```

| ما يُحفظ | أين في MongoDB |
|---|---|
| محتوى كل قسم (نفس شكل ملفات JSON) | مجموعة `content`، مستند لكل قسم |
| النسخ السابقة لكل قسم (آخر 30) | `content_history` |
| الصور والفيديوهات وملفات PDF | GridFS: `media.files` و`media.chunks` |
| طلبات نموذج التواصل | `messages` |

### الإعداد لأول مرة

1. أنشئ قاعدة بيانات مجانية على [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register): أنشئ Cluster مجاني (M0)، ثم **Database Access** لإضافة مستخدم وكلمة مرور، ثم **Network Access** واسمح بـ `0.0.0.0/0`، ثم **Connect → Drivers** وانسخ رابط الاتصال.
2. انسخ `.env.example` إلى `.env` واملأ `MONGODB_URI` و`ADMIN_PASSWORD` و`SESSION_SECRET`.
3. انقل المحتوى الحالي إلى قاعدة البيانات:

```bash
npm install
npm run seed              # ينسخ ملفات public/data إلى MongoDB (لا يستبدل الموجود)
npm run seed -- --media   # ويرفع أيضاً كل الصور والفيديوهات المستخدمة إلى MongoDB
npm run seed -- --force   # يستبدل ما في قاعدة البيانات بمحتوى الملفات
```

4. شغّل الموقع:

```bash
npm run build && npm start   # الموقع ولوحة التحكم والـ API على http://localhost:3000
```

أثناء التطوير شغّل `npm run server` و`npm run dev` معاً؛ يوجّه Vite طلبات `/api` إلى الخادم.

### لوحة التحكم

افتح `/admin.html` وادخل بكلمة المرور `ADMIN_PASSWORD`.

- **المحتوى**: كل قسم يظهر كنموذج: حقول للنصوص، وأزرار لإضافة العناصر وترتيبها ونسخها وحذفها، و«رفع ملف» أو «من المكتبة» لكل صورة أو فيديو. زر «تحرير JSON» للتعديل المباشر.
- **التحقق قبل الحفظ**: يفحص الخادم المحتوى بالقواعد نفسها التي يعرض بها الموقع؛ إذا كان فيه خطأ لا يُحفظ، وتفتح اللوحة الحقل المقصود وتعلّمه بالأحمر.
- **النسخ السابقة**: كل حفظ يحتفظ بالنسخة التي قبله، ويمكن استرجاع أي منها.
- **مكتبة الملفات**: رفع بالسحب والإفلات، وبحث، ونسخ رابط، وحذف. المقبول: JPG وPNG وWebP وGIF وAVIF، وفيديو MP4 وWebM وMOV، وPDF، حتى `MAX_UPLOAD_MB` (100 م.ب افتراضياً).
- **رسائل التواصل**: طلبات الزوار مع روابط الاتصال وواتساب، وتعليمها كمقروءة أو حذفها.

يظهر نموذج «اطلب استشارة» في الموقع فقط عندما يكون الخادم متاحاً. للحماية من الرسائل المزعجة فيه حقل مخفي وحد أقصى 5 رسائل كل 10 دقائق لكل زائر.

### النشر مع قاعدة البيانات

GitHub Pages يستضيف ملفات ثابتة فقط ولا يشغّل خادماً، لذلك يُنشر الخادم على استضافة Node.js. الأسهل [Render](https://render.com):

1. **New → Blueprint** واختر هذا المستودع؛ يقرأ الإعدادات من `render.yaml`.
2. أدخل `MONGODB_URI` و`ADMIN_PASSWORD` عند الطلب (`SESSION_SECRET` يُولَّد تلقائياً).
3. بعد النشر افتح `https://<اسم-الخدمة>.onrender.com/admin.html`.

الخادم يستضيف الموقع ولوحة التحكم معاً. الخطة المجانية في Render تنام بعد 15 دقيقة دون زيارات، فتتأخر أول زيارة بعدها؛ إن تأخر الخادم أكثر من 6 ثوانٍ يعرض الموقع محتوى الملفات بدل الانتظار.

لجعل نسخة GitHub Pages تقرأ من قاعدة البيانات أيضاً: أضف في المستودع **Settings → Secrets and variables → Actions → Variables** متغيراً باسم `VITE_API_URL` وقيمته عنوان الخادم، وتأكد أن `CORS_ORIGINS` في الخادم يحتوي `https://magiclooksa.github.io`.

> صور معاينة الروابط (مجلد `public/og`) تُبنى وقت البناء من الملفات، فلا تتغير بتعديل المحتوى من اللوحة.

## ملفات المحتوى (public/data)

ملفات JSON هي المحتوى الأولي الذي ينقله `npm run seed`، والمحتوى الاحتياطي عندما لا يتوفر الخادم. بعد نقل المحتوى إلى قاعدة البيانات عدّله من لوحة التحكم؛ تعديل الملفات بعدها لا يظهر إلا عبر `npm run seed -- --force`.

| الملف | المحتوى |
|---|---|
| `company.json` | الاسم، والنبذة، والرؤية والرسالة والقيمة، وقسم التصميم الداخلي |
| `services.json` | الخدمات وأيقوناتها |
| `products.json` | فئات المنتجات |
| `advantages.json` | لماذا النظرة الساحرة |
| `journey.json` | خطوات رحلة العمل |
| `levels.json` | مستويات التعامل |
| `projects.json` | المشاريع وصورها وطريقة عرض كل مشروع |
| `clients.json` | فئات العملاء، والشركاء، والشهادات والمشاركات |
| `contact.json` | الجوال، والبريد، والموقع، والعنوان، ورابط الخريطة |

**القيمة `null` تعني أن المعلومة لم تتوفر بعد**، فتظهر في الصفحة بين أقواس مثل [رقم الجوال]. اكتب القيمة بدلها لتظهر.

### إضافة الصور والفيديوهات

خلفية الـ hero تُحدد في الحقل `hero` داخل `public/data/company.json`. يستخدم الموقع الفيديو المحدد مع صورة `poster` أثناء التحميل، وتدرّج داكن فوقه لإظهار الشعار والنصوص. تعمل الخلفية تلقائياً وبشكل متكرر مع كتم الصوت وزر لتفعيله. تملأ الخلفية مساحة القسم، لذلك قد تُقص أطرافها لتناسب شاشة الجوال؛ إعدادات نسب عرض صور وفيديوهات المعارض مستقلة عنها.

ضع الصور في `public/images/projects` (أو أي مجلد داخل `public`)، ثم اكتب مسارها في `src`:

```json
{ "src": "images/projects/villa-majlis.jpg", "caption": "المجلس الرئيسي" }
```

يمكن خلط الصور والفيديوهات داخل قائمة `images` نفسها، وكذلك استخدام الفيديو في أي حقل وسائط. ضع الفيديو في `public/videos/products` ثم أضف مثلاً:

```json
{
  "type": "video",
  "src": "videos/products/majlis.mp4",
  "poster": "images/products/01-360-view-angles-bfa3cf86ae.webp",
  "caption": "جولة في المجلس"
}
```

حقل `poster` اختياري. يُكتشف الفيديو تلقائياً من امتداد الملف، واستخدم `type: "video"` للروابط التي لا تحتوي على امتداد. يُفضل MP4 بترميز H.264 لتوافق المتصفحات.

الضغط على الصورة يفتحها كاملة في شاشة عرض خاصة، مع زر للتكبير والتصغير وإمكانية تحريك الصورة المكبرة بالتمرير أو اللمس. يُغلق العارض بزر «إغلاق» أو مفتاح Escape، ويتوقف تشغيل الفيديو في الخلفية أثناء عرض الصورة.

يمكن تحديد نسبة العرض لكل صورة أو فيديو بإضافة `aspectRatio` إلى العنصر نفسه في JSON:

```json
{
  "images": [
    {
      "src": "images/projects/villa-majlis.jpg",
      "caption": "المجلس الرئيسي",
      "aspectRatio": "16:9"
    },
    {
      "src": "videos/products/majlis.mp4",
      "type": "video",
      "caption": "جولة في المجلس",
      "aspectRatio": "9:16"
    }
  ]
}
```

- `"9:16"`: إطار طولي.
- `"16:9"`: إطار أفقي.
- `"auto"` أو `null` أو حذف الحقل: اختيار تلقائي من أبعاد الملف، طولي للملفات الطولية وأفقي للأفقية والمربعة.

النسبة المحددة في JSON لها الأولوية حتى لو اختلفت عن أبعاد الملف، وتُطبق قبل تحميله وفي شاشة تكبير الصور أيضاً. تظهر الوسائط كاملة دون تمديد أو قص، مع فراغ حولها إذا اختلفت نسبتها عن الإطار. في عرض `compare` يحدد حقل `before.aspectRatio` إطار المقارنة المشترك؛ يُفضل إعطاء `before` و`after` النسبة نفسها. في الوضع التلقائي يستخدم الإطار `16:9` مؤقتاً حتى تُحمّل أبعاد الملف.

تعمل الفيديوهات تلقائياً وبشكل متكرر داخل الصفحة، وتبدأ مكتومة مع زر «تشغيل الصوت» يتحول إلى «كتم الصوت». يتوقف الفيديو عند خروجه من الشاشة أو إخفاء تبويب الصفحة أو الانتقال إلى شريحة أخرى. يبقى عرض الشرائح على الفيديو ليتمكن من التكرار حتى يختار الزائر عنصراً آخر. إذا منع المتصفح التشغيل التلقائي تظهر أدوات التشغيل اليدوي.

### طرق عرض المشاريع

لكل مشروع حقل `layout`:

- `mosaic`: صورة كبيرة وحولها صور أصغر.
- `slideshow`: عرض يتبدل تلقائياً مع صور مصغرة للتنقل.
- `compare`: شريط قبل وبعد، ويحتاج الحقلين `before` و`after`، والصور في `images` تظهر بجانبه.
- `filmstrip`: شريط صور طولية يتحرك بالسحب أو بالأسهم.

`colors` قائمة ألوان HEX تظهر كعينات، مثل `["#7B5D08", "#F4F0E8"]`.

إذا كان في ملف خطأ، تعرض الصفحة اسم الملف والحقل المقصود، مثل `projects.json[0].colors[0]`.

## البنية

يتبع الكود البنية النظيفة (Clean Architecture): كل طبقة تعتمد على الطبقة التي تحتها فقط.

```
src/
├── domain/            الكيانات والواجهات، دون أي اعتماد خارجي
│   ├── entities.ts          نموذج الملف التعريفي (Profile وProject وغيرها)
│   └── ProfileRepository.ts واجهة مصدر البيانات
├── application/       حالات الاستخدام
│   └── GetProfile.ts        تحميل الملف التعريفي وتجهيزه للعرض
├── infrastructure/    مصادر البيانات الفعلية
│   ├── decoders.ts          أدوات تحقق صغيرة من بيانات JSON
│   ├── schemas.ts           شكل كل ملف JSON (يستخدمه الخادم أيضاً للتحقق قبل الحفظ)
│   ├── api.ts               القراءة من الـ API مع الرجوع للملفات، وإرسال رسائل التواصل
│   └── JsonProfileRepository.ts قراءة الأقسام
├── presentation/      العرض والتفاعل
│   ├── App.ts               تركيب الصفحة
│   ├── components/          قسم لكل ملف
│   ├── galleries/           طرق عرض المشاريع الأربع
│   ├── behaviors/           الحركة عند التمرير، وحالة القائمة، وخط رحلة العمل
│   ├── dom.ts               منشئ عناصر آمن (لا يستخدم innerHTML للنصوص)
│   └── icons.ts             الأيقونات ونقش الهوية
├── admin/             لوحة التحكم (admin.html)
│   ├── editor.ts            نموذج يُبنى من شكل المحتوى نفسه
│   ├── media.ts             مكتبة الملفات ونافذة الاختيار
│   └── messages.ts          رسائل التواصل
├── styles/            tokens وbase وsections وgalleries وadmin
└── main.ts            نقطة التركيب: تربط الطبقات ببعضها

server/                الخادم (Express + MongoDB)
├── index.ts               التشغيل
├── app.ts                 المسارات، وCORS، واستضافة dist
├── auth.ts                تسجيل الدخول والتوكن وحد المحاولات
├── sections.ts            الأقسام القابلة للتعديل وقواعد التحقق لكل منها
├── routes/                content وfiles (GridFS) وmessages
└── scripts/seed.ts        نقل public/data والوسائط إلى MongoDB
```

الصفحات تقرأ المحتوى عبر `ApiContent`: طلب واحد إلى `/api/content` يجلب كل الأقسام، وأي قسم غير موجود في قاعدة البيانات أو أي فشل في الاتصال يرجع إلى ملف JSON المقابل.

### الـ API

| الطلب | الوصف | يحتاج دخول |
|---|---|---|
| `GET /api/content` | كل الأقسام | لا |
| `GET /api/content/:key` | قسم واحد | لا |
| `PUT /api/content/:key` | حفظ قسم بعد التحقق منه | نعم |
| `GET /api/content/:key/history` و`POST …/history/:id/restore` | النسخ السابقة واسترجاعها | نعم |
| `POST /api/files` (حقل `files`) و`GET` و`DELETE /api/files/:id` | رفع الملفات وعرضها وحذفها | نعم |
| `GET /api/files/:id/:name` | عرض ملف (يدعم Range لتشغيل الفيديو) | لا |
| `POST /api/messages` | إرسال طلب من نموذج التواصل | لا |
| `GET`/`PATCH`/`DELETE /api/messages` | قراءة الرسائل وإدارتها | نعم |
| `POST /api/auth/login` | `{ "password": "…" }` ← توكن صالح 7 أيام | لا |

## الحركة

- شعار LM يظهر عند فتح الصفحة وتمر عليه لمعة ذهبية.
- الأقسام تصعد بنعومة عند ظهورها، وخط رحلة العمل يمتلئ خطوة بعد خطوة.
- نقش الهوية يتحرك ببطء في الخلفية، والأيقونات ترتسم عند مرور الماوس.
- كل الحركة تتوقف لمن فعّل خيار تقليل الحركة في جهازه، والمحتوى ظاهر دائماً دون انتظار الحركة.
- الوضع الداكن يتبع إعداد الجهاز.
